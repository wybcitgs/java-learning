## 泛型验收（8 题：4 全对 / 2 半对 / 2 错）
- ✅ 泛型两个好处：统一数据类型 + 把运行期问题提前到编译期
- ✅ 三条细节：不能写基本类型 / 可传本类或子类 / 不写默认 Object
- ✅ 为什么 `Object[]` 而不是 `E[]`：泛型运行时擦除，`new E[]` 编译不过
- 半 ✅ `(E)` 强转：**不是为了避免类型错误，而是让编译器闭嘴**——运行时擦除，强转永不抛异常；真正检查发生在**调用点**（`String s = list.get(0)` 处编译器插入强转）
- ❌ **泛型方法 `<E>` 的位置**：必须写在**返回值类型前面**（修饰符 → `<E>` → 返回值 → 方法名）；`<T> T max(...)` 里第一个是声明、第二个是返回值，合法
- 半 ✅ 泛型接口两种实现：确定型 `implements List<String>` vs 延续型 `implements List<E>`（后者更通用，`ArrayList` 就是这种）
- ❌ **`List<?>` 能读不能写**：`list3.add("a")` 编译错误，只能 `add(null)`
- ✅ 手写泛型方法 `swap(T[] arr, int i, int j)`，`T temp` 三步交换，标准

## 今天补透的两个概念
### ① 泛型是编译期的纸规矩，运行时查无此人
- 类型擦除：`E` 编译后变 `Object`
- `new E[]` 不行；`(E)` 强转不检查；检查只在**调用点**插入
- 这解释了 `MyArraylist` 为什么用 `Object[] obj` + `(E)` 强转

### ② extends / super 的分工（PECS）
| 写法 | 往里写 | 读出类型 | 角色 |
|---|---|---|---|
| `?` | 只能 null | Object | 只读 |
| `? extends Number` | 只能 null | Number | 生产者（读） |
| `? super Integer` | 可写 Integer | Object | 消费者（写） |

- **判断法**：拿它主要读 → extends；主要写 → super；又读又写 → 别用通配符，直接写具体类型或 `<T>`
- 本质：`extends` 保证"读出的东西至少是 Number"，`super` 保证"写进去的东西能被容纳"
- 顺带纠正：**Number 是包装类（Integer/Double/Long）的父类，不是八大基本类型的父类**
