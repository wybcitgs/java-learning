## 假会清单（重点，动手时对照）

### ① lambda 的三段语义（自测 Q2，专项复测未答）
```java
Comparator<Integer> cmp = (a, b) -> b - a;
//                        ↑参数列表 ↑箭头 ↑方法体
```
- `()` 对应接口方法的**参数列表**（不是"变量类型"）
- 右侧对应**重写方法的大括号内容**
- **被省掉的**：`new 接口名()`、`@Override`、方法名、返回值类型（参数类型也可省）
- 专项复测第 1 题改写正确 ✅（`(a, b) -> b - a`）；**省掉的四样**：`new Comparator<Integer>()`、`@Override`、方法名 `compare`、返回值类型 `int`（参数类型也可省）

### ② lambda 的两种合法形式（自测 Q4 错）
```java
(a, b) -> a + b;                // ✅ 表达式形式：不能写 return
(a, b) -> { return a + b; };    // ✅ 语句块形式：必须有 return
(a, b) -> return a + b;         // ❌ 不存在这种写法
```
- **有返回值 → 方法体必须给返回值**；`{ "v" + x; }` 这种"有值没 return"也编译不过
- 专项复测第 2 题未答，此项**待复测**

### ③ 泛型通配符的读写方向（自测 Q16 半对）
| 写法 | 往里写 | 读出类型 | 角色 |
|---|---|---|---|
| `?` | 只能 null | Object | 只读 |
| `? extends Number` | 只能 null | **Number** | 生产者（读） |
| `? super Integer` | 可写 Integer | Object | 消费者（写） |

- 我答"`? extends` 读不出来"——**能读，读出的是 Number**，只是不能当 Integer 用
- 判断法：主要读 → `extends`；主要写 → `super`；又读又写 → 别用通配符
- 专项复测第 3 题未答，**待复测**

### ④ ArrayList 的复杂度与选型（自测 Q11 半对）
- **ArrayList 查询 O(1) 快**（下标直接定位），增删慢（要挪元素）
- LinkedList 查询 O(n) 慢（头尾 O(1)），增删快（改指针）
- **选型：默认 ArrayList；频繁头尾增删才用 LinkedList**
- 专项复测第 4 题未答，**待复测**

### ⑤ 二叉查找树规则与退化（自测 Q17 半对）
- 规则：**左子树所有节点 < 根 < 右子树所有节点**（递归成立）
- 查找速度取决于**树高**
- 有序数据依次插入 → 退化成斜链 → **O(n)**，这正是平衡树要解决的问题
- 专项复测第 5 题未答，**待复测**

### ⑥ 红黑树 vs 平衡二叉树（自测 Q18 半对）
- 红黑树**不是严格平衡**（自测答对了核心）
- 补充：靠颜色规则保证**最长路径 ≤ 最短路径 2 倍**；查询略慢、旋转更少 → TreeMap/TreeSet 底层
- AVL 严格平衡（左右高度差 ≤ 1），查询更快、旋转更多

### ⑦ HashSet 去重原理（自测 Q19 半对）
- 底层：**数组 + 链表 + 红黑树**（链表过长转红黑树）
- 去重靠 **hashCode + equals** 两步：hashCode 定位桶，equals 比较桶内元素
- **只重写 equals** → hashCode 仍按地址算 → 内容相同的对象落不同桶 → 判不重复
- **只重写 hashCode** → 同桶但 equals 比地址 → 判不重复
- **两个都必须重写**；专项复测第 6 题未答，**待复测**

### ⑧ 异常名（自测 Q9 半对）
- 遍历中用集合自身方法增删 → **`ConcurrentModificationException`**
- 要用 `iterator.remove()` / `ListIterator.add()`

### ⑨ 其他小订正
- **default 方法不算抽象方法**，不占函数式接口的名额（有 default 的接口仍可用 lambda）
- Collection 体系除了 List、Set，还有 **Queue** 分支
