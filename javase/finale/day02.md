## 2. 补漏 5 项（重检，18:17）

**结果：5 题全对**

1) **HashMap 底层** = 数组 `Node[] table` + 链表 + 红黑树；容量是 2 的幂因为 `n-1` 是全 1 掩码，此时 `(n-1) & hash` 才等价 `hash % n`，且位运算更快
2) **`toMap` 重复键** → `IllegalStateException: Duplicate key`；解法 `toMap(键, 值, (oldVal, newVal) -> newVal)`
3) **TreeMap** → 键须 `Comparable` 或传 `Comparator`，否则 `ClassCastException`；`compareTo` 返回 0 = 重复键覆盖
4) **拆箱 NPE** → `NullPointerException`，编译器插入 `i.intValue()`；高频场景 `int x = map.get(不存在的key)`
5) **put 六步** → 顺序、条件、树化双条件、「先 size++ 再比阈值」全部说对

## 3. HashMap put 六步（今日掌握）

1) 表为空或长度为 0 → `resize()` 初始化，默认容量 16
2) 定位桶 `(n-1) & hash`，桶为空 → `new Node` 直接放入，结束
3) 桶首节点 key 相同（hash 相同 && (`==` 或 `equals`)）→ 记下，准备覆盖
4) 桶首是 `TreeNode` → `putTreeVal` 走红黑树插入
5) 否则遍历链表：中途找到相同 key → 准备覆盖；走到尾 → 尾插新节点，判断树化（**链表 ≥ 8 且 数组 ≥ 64**）
6) 找到相同 key → 覆盖并返回**旧值**；没找到 → **`size++`**，超过 `容量 × 0.75` 扩容，返回 **null**

**记忆法**：前两步判位置（表建好没、桶空不空），中间三步判形态（同一 key / 树 / 链表，互斥），最后一步判结果。三个数字钉首尾：**16 / 8 与 64 / 0.75**。

### 今天暴露的两个硬错误

**变量存储位置全说反了**

| 变量 | 位置 | 默认值 |
|---|---|---|
| 成员变量 | **堆**（跟对象） | 有默认值（0 / false / null） |
| 静态变量 | **方法区** | 有默认值 |
| 局部变量 | **栈** | **无默认值**，必须手动初始化 |

一句话：栈放局部变量和方法调用，堆放对象和成员变量，方法区放静态数据。

**ArrayList 扩容参数记错**
默认容量 **10**（不是 16，16 是 HashMap），扩容 **1.5 倍**（`old + (old >> 1)`），首次 `add` 才真正分配数组。

### 必须在明天前记住的三条

1) **重载 vs 重写**：重载在同类的「同名不同参」，编译期静态分派；重写是子类的「同名同参」，运行期动态绑定，访问权限不能更严、不能抛更宽的受检异常
2) **JDK8 时间类三条优势**：不可变（线程安全）、类型分工明确（`LocalDate` / `LocalTime` / `LocalDateTime` / `ZonedDateTime`）、`DateTimeFormatter` 线程安全
3) **BigDecimal**：`new BigDecimal(0.1)` 传 double 会带入精度误差，必须用 `new BigDecimal("0.1")` 字符串构造

### 两处反驳，用户是对的

- **第 6 题我题干表述不准**：父类引用只能调用**父类中声明过的方法**（编译期看引用类型），运行时执行子类重写的版本；调用子类特有方法必须先向下转型
- **第 3 题超纲**：`StringBuffer` 未学；补一句备用——`StringBuffer` = 加了 synchronized 的 StringBuilder，线程安全但慢，单线程一律用 StringBuilder
