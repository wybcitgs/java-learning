### ① 多态三前提（只能说出 1 条）
- **正确**：① 有继承/实现关系 ② **有方法重写** ③ **父类引用指向子类对象**

- **记法：有爹、有重写、爹指儿**——三条缺一不可

### ② 多态的好处与坏处
- **好处**：一个方法接住一整族对象（`void feed(Animal a)` 通吃 Cat/Dog/Pig，新动物不用改代码）
- **坏处**：父类引用**调不了子类特有方法**（`a.catchMouse()` 编译就拦）
- **解决**：**向下转型** `Cat c = (Cat) a;`（向上转型是自动的，向下要手动、有风险）
- 我只会写代码（第 2 题三小问全对），**但说不出术语**

### ③ 什么时候用继承，什么时候用接口 ⭐（自测第 7 题，当时想了很久）
**口诀：is-a 用继承，can-do 用接口。**

| | 继承（extends）| 接口（implements）|
|---|---|---|
| 表达 | **is-a**：「**是什么**」| **can-do**：「**能做什么**」|
| 例子 | `Cat extends Animal`——猫**是**动物 | `Bird implements Flyable`——鸟**能**飞 |
| 数量 | **只能 1 个**（单继承）| **可以多个**（多实现）|
| 适用 | 有天然血缘/共性，复用父类的字段和方法 | 附加能力，跟"是什么"无关（飞机也能飞） |

**判断步骤**：
1. 先问「B **是** A 吗？」→ 是 → **继承**
2. 再问「B **能做** A 这件事吗？」→ 是 → **接口**
3. 两者都成立时（如 `BasketballPlayer` 既 is-a `Athlete`、又能说英语）→ **继承 + 接口一起用**

**P119 综合练习就是这么设计的**：`Person → Athlete → Coach → ...` 三层继承管身份，`说英语` 用接口管能力。

### ③-b 抽象类 vs 接口（表述混乱）
- **最本质区别**：抽象类是 **is-a（是什么）**，接口是 **can-do（能做什么）**
- 数量：类**单继承**（extends 一个），接口**多实现**（implements 多个）
- 同上：口诀我会，**但换个问法就接不上**

### ④ `abstract` 修饰什么（答漏）
- `abstract` **能修饰类和 方法**，不只是方法
- 抽象方法三特点：① **没有方法体** ② 必须在抽象类里 ③ 子类必须重写（除非子类也是抽象类）

### ⑤ 抽象方法的语法（第 12 题答 A，错）
- `A. abstract void f() { }` ❌ **有花括号 = 有方法体 → 报错**
- `B. abstract void f();` ✅ 分号结尾
- `C. class C { abstract void f(); }` ❌ 类没声明 abstract
- **单向规则：有抽象方法 → 必须是抽象类；但抽象类不一定要有抽象方法** ✅（抽象类里可以有普通方法，已补验证通过）

### ⑥ 匿名内部类（表述不准）
- 我答「没有名字的类」——**不准**
- **正确**：匿名内部类 = **没有名字的类对象**（一次性地创建子类/实现类的实例）
- 本质是**对象**，那个"类"只是顺带定义的，用完即弃

### ⑦ `"abc" == "abc"` 的理由（结果对，理由反了）
- 结果我答对了（true / false），但**理由说反**——我答"前面比的是数值"
- **正确**：**两次都是比地址**
  - `"abc" == "abc"` → 字面量存**常量池**，两次是**同一个对象** → 地址相同 → true
  - `new String("abc") == "abc"` → new **强制在堆里新建** → 地址不同 → false
- 区别在**地址是否相同**，不在"比什么"

### ⑧ `=` 才能接住（本周最核心的洞，犯了三次）
- 我以为 `return s` 能"接住"上一行的结果 —— **错**
  - **`return` 是交出去，`=` 才是接住**；`return s` 交出去的还是老的 `s`
- 正确：`s = s.replace('l','L');`
- **铁律**：String 的所有"修改"方法（substring / replace / trim / toUpperCase / split…）**都不改自己，只返回新串**；**不写 `s = ` 就等于白干**
- 判断小测（已通过）：`s.trim(); return s;` 不能返回去空格结果 ✅ / `String t = s.toUpperCase();` 的 `s` 没变 ✅

## 扎实的（不用再看）

- 多态的编译/运行规则：**编译看左边，运行看右边**（第 2 题三小问全对）
- 抽象类不可实例化；子类不实现抽象方法 → **子类也声明 abstract**

- `new int[3]` → `[0,0,0]`；`new String[3]` → `[null,null,null]`
- **循环里数组会滚动变化**（只有第一轮碰的是原始数组）
- is-a / can-do 口诀 ✅

## 认知突破（本周最值钱的一条）

**循环体内对数组/集合做原地修改，下一轮看到的就不是原样了。**

以 `"abc"` 打乱为例：

| 轮次 | 我以为在操作的 | 实际在操作的 |
|---|---|---|
| i=0 | `[a,b,c]` | `[a,b,c]` ← 只有第一轮是原值 |
| i=1 | `[a,b,c]` ❌ | `[c,b,a]` ✅ |
| i=2 | `[a,b,c]` ❌ | `[b,c,a]` ✅ |

**推广**：冒泡排序、插入排序、双指针交换（344）、快排分区、数组去重**全是这个道理**。
分析循环要**跟着状态走**，不能盯着初始值。
