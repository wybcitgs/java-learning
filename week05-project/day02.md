## 今天发现并修复的 bug（contains 判重）
- 原代码：循环拿 `list.size()` 当 `username` 的下标，且只比较**同下标单个字符**就返回 true
- 两个错误叠加：
  1. **循环对象搞混**：`i` 遍历用户列表，却拿去戳 `username`——用户数 > 用户名长度时直接 `StringIndexOutOfBoundsException` 崩溃
  2. **比较逻辑错**：注册过 `abc123` 后再注册 `abc999`，首字符 `'a'=='a'` 就返回 true → **误判"已存在"**（把必要条件当充分条件）
- **原理**：两串相等 = 长度相等 **且** 每个下标字符都相等；`equals` 内部先比长度再逐位比，完整判定交给它；`i` 只该有"第几个用户"一个身份，不该兼职"第几个字符"
- 修复：循环体改 `list.get(i).getUsername().equals(username)` **整串比较**
- 不能用 `list.contains(username)` 捷径——集合里装的是 `User` 不是 `String`，手写循环是必须的
- **修复后验证 ✅**：注册 `abc123` → 再注册 `abc999` → 注册成功（修复前会被误杀）

## 8 题快检（6 全对 / 2 半对）
- ✅ 空参构造：username/password 为 null，id 已在构造里生成；有参构造同样自动生成 id + status=true
- ✅ list 写在 start() 再传参：login/register 共享同一集合；写在 register 内部 = 每次新集合数据不互通（Java 值传递传的是引用副本，两边指向同一对象）
- ✅ continue 跳回 while 条件 → 重新录入；卫语句平铺避免 if 嵌套
- ✅ checkLen 参数化：复用 + 改范围只动一处
- 半 ✅ 裸下标约定：靠命名 + 返回定序维持；若 checkNumber 误写 `count[2]>0` → 所有正常用户名被拒且提示误导，**写错不报错只出错误行为**
- ✅ **自查出真 bug**：原来 checkNumber/checkPassword 一模一样，对密码对、对用户名过严（纯字母 `abc` 被拒）
  - 需求核对：用户名「不能是纯数字」→ **纯字母合法**；密码「字母加数字组合」→ **两者都必须有**
  - 修正过程踩了两个小坑：`count[1] >= 0` 永真式（计数不可能为负，等于没写）；改回 `count[1] > 0` 又把纯字母拒了
  - **最终正确版**：checkNumber = `count[0] > 0 && count[2] == 0`（必须有字母排除纯数字，数字可无）；checkPassword = `count[0] > 0 && count[1] > 0 && count[2] == 0`（两者都必须有）
  - 验证 ✅：`abc` 通过 / `123` 拒 / `ab!` 拒
- 半 ✅ 登录思路：只答了"遍历 + equals 找到匹配"——实际是**两步查**：第一步查用户名存在（不存在→"请先注册"），第二步比对已找到 User 的密码（不一致→"密码错"），两步分开错误提示才能分开
