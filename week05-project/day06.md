### 136 只出现一次的数字 ✅ 暴力 794ms → 异或 1ms（99.88%）
- **暴力版自己写的**：嵌套循环数次数，内层循环 3 个 bug（起点 `nums.length` 越界 / 终点 `>0` 漏下标 0 / **自己和自己比了**——每个元素 count 至少 1，count==0 永不成立）
- **三步法走完**：暴力过 → 看异或思路 → 关掉默写三行版
- **新知识 ①（题解学的，非课程内容）：`^` 异或运算符**
  - 位运算：逐位比较，相同得 0 不同得 1
  - 两条铁律：`a ^ a = 0`（自己消灭自己）、`a ^ 0 = a`（隐身衣）；交换律结合律成立
  - 全数组异或 = 成对的互相消灭，落单的活下来。O(n) 时间 O(1) 空间
- **新知识 ②（课程 P133-134 没讲，Day01 验收时挂起的）：增强 for**
  - `for (int num : nums)` = 把数组每个元素依次取出赋给 num
  - 用法取舍：**要下标用传统 for，只过元素用增强 for**；遍历的是元素副本

### 283 移动零 ✅ 1ms（99.98%）—— 三次迭代，连环 bug
- 双指针思路自己成型：fast 扫、low 指下一个非零该放的位置，扫完补零
- **事故链**（值得反复复盘的那种）：
  1. `j <= fast-low` → 零个数=0 时多跑一次 → `ArrayIndexOutOfBoundsException`（[1]、[2,1] 挂）
  2. 改 `<` → 又欠补（[0,1,0,3,12] 只补 1 个零）——因为 `low` 在循环里自增，`fast-low` **每轮都在缩小**
  3. 修法：**先把个数定格** `int count = fast-low;` 再用 count 做判据
- ⭐ **本题终极教训（比题值钱）**：
  > **循环条件里引用的量，必须是循环过程中不变的（或明确知道它怎么变、判据跟着对）。写完计数循环先问：这个判据，第 1 轮和第 n 轮取值一样吗？**
- 调试方法论收获：**"本地测试过"不等于过**——力扣挂的用例是边界（无零数组），以后提交前自喂三类边界：空操作 / 极端 / 单元素

### 169 多数元素 ✅ 6ms —— 排序路线三行收官
- `Arrays.sort(nums)` + `nums[nums.length/2]`
- **原理**：排序把"统计问题"变"位置问题"——多数元素 > n/2 个，连续块必盖住中位（奇偶下标 `length/2` 通吃，两头晃都躲不开中间）
- `Arrays.sort` = JDK 自带排序（官方黑盒），会用即可；977 的手写冒泡是自己的第一个排序
- 路线 A（HashMap 计数）留 week06 下部 P2-26 学到时回来重写此题
