## 假会清单（重点，动手时对照）

### ① ArrayList 两个 remove 重载（Day01 验收记反，复验 3/3 才钉死）
- `list.remove(0)` → 实参是 **int 字面量** → `remove(int index)`，按**索引**删
- `list.remove("0")` → 实参是**对象** → `remove(Object)`，按**值**删
- `ArrayList<Integer>` 想删**值为 0** 的元素：必须 `list.remove(Integer.valueOf(0))`
- **口诀：int 字面量按索引，对象按值**
- 行为差异：`remove(int)` 越界抛 `IndexOutOfBoundsException`；`remove(Object)` 找不到**返回 false 不报错**

### ② 类型细节两连（Day03 快检）
- **char 参与算术自动升级成 int**：`'a' + i` 是 int，`add` 要 Character，int 装箱是 Integer → 必须 `(char)` 强转回去
- **String 不可变 → 改字符要换容器**：`StringBuilder`（拼）→ `char[]`（交换）→ `new String(arr)`（成品）

### ③ "写错不报错、只出错误行为"的一族坑（本周最大主题）
| 坑 | 错在哪 | 修法 |
|---|---|---|
| 三元优先级 `damage /= 2>1 ? ...` | 条件部分是"整个除法的结果"，按空格目测分组 | `damage = damage / 2 > 1 ? damage / 2 : 1` |
| 血条整数除法 `HP / maxHP` | int 除 int 丢小数，50/100=0 | `HP * 1.0 / maxHP` |
| 增强被自己抹掉 `c.HP+=10; c.HP=c.maxHP;` | 下一行覆盖上一行 | `c.maxHP += 10; c.HP = c.maxHP;` |
| `wins` 从未自增 | 条件变量没人维护，`if(wins!=0)` 永不成立 | 战斗结束时 `wins++` |
| 循环判据活动变化（283 移动零） | `fast-low` 里的 `low` 在循环里自增，判据每轮变小 | 先定格 `int count = fast-low;` 再循环 |
| 双重扣防御（重写引入） | `calculateDamage` 和 `takeDamage` 都减防御 | 一个计算只留一个权威出口 |

### ④ 变量命名/语义坑
- `contains` 判重写成"同下标单字符比较" → **整串 equals**；单字符相等只是必要条件
- 校验嵌套错位：长度校验里塞 `contains` → 长度非法但用户名不重复时被放行
- `count++` 两处 → 场次跳号；一个计数器只在一处更新

### ⑤ 校验规则的细节（Day02 自查发现）
- 用户名「不能是纯数字」→ **纯字母合法**：`count[0]>0 && count[2]==0`
- 密码「字母加数字的组合」→ **两者都必须有**：`count[0]>0 && count[1]>0 && count[2]==0`
- 永真式警报：`count[1] >= 0` 恒成立，等于没写

## 认知突破（本周最值钱的三条）

### ① 写完运算，代一个具体值手动走一遍

本周 9 个坑里 6 个是"编译能过、测试能过、结果是错的"：整数除法、三元优先级、双出口扣防、增强被覆盖、活动判据、count 双加。
**共同点：写的时候觉得对，值从没真的走一遍。** 以后涉及运算的代码，写完立刻代值（`50/100`、`[0,1,0,3,12]`）手算。

### ② 一个计算只留一个权威出口

攻击扣血这件事，`calculateDamage` 和 `takeDamage` 都改就会算两次（坦克被打反而回血）；`count` 两个分支都加就会跳号。
**凡是"两处都能改同一个量"的设计，最后都会双算或互相抵消。**

### ③ 循环条件里的量，必须是循环中不变的

283 移动零的终极教训：
> 循环判据里的 `fast-low` 藏着会自增的 `low`，每轮取值都在变。写完计数循环先问：**这个判据，第 1 轮和第 n 轮取值一样吗？**
