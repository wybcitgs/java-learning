## 今天学了（下部 P52–62 异常，11 集 1h47m）

### 异常体系
```
Throwable
├── Error                    ← 系统级错误（OOM、StackOverflowError），程序无法处理，一般用不到
└── Exception
    ├── RuntimeException     ← 运行时异常（非受检）
    └── 其他 Exception       ← 编译时异常（受检）
```

### 编译时异常 vs 运行时异常
- **编译时异常**（受检）：`Exception` 的非 `RuntimeException` 子类。方法里不 `try-catch` 也不 `throws` 声明，**编译直接失败**——编译器强制检查，目的就是提醒程序员「这里有风险，你得管」
- **运行时异常**（非受检）：`RuntimeException` 及子类。编译器放行，多由参数错误、越界、空指针导致，出事才算

### 异常在代码中的两个作用
1. **对内**：异常信息是用来查 bug 的关键线索（`printStackTrace` 的堆栈）
2. **对外**：可以作为方法的一种**特殊返回值**，告知调用者内部执行情况

### try-catch
```java
try {
    // 可能出问题的代码
} catch (ArithmeticException e) {
    e.printStackTrace();
}
```
- **catch 顺序**：子类异常必须写在父类前面，否则父类 catch 先把子类吃掉 → 编译报错
- ⚠️ 本课程 P52–62 **没有讲 `finally`**（黑马新版把 finally 放到 IO 流那章），见下文补充

### 异常常用三方法
| 方法 | 输出 |
|---|---|
| `getMessage()` | 详细的异常消息字符串 |
| `toString()` | 简短的异常描述：**类名: 消息** |
| `printStackTrace()` | 把完整堆栈打印到控制台（红字），**查 bug 主要靠它** |

### throw vs throws
| | `throw` | `throws` |
|---|---|---|
| 位置 | 方法**体内** | 方法**签名**上 |
| 作用 | 真的抛出一个异常对象 | 声明「本方法可能抛」，交给调用者处理 |
| 后面跟 | 异常**对象**（`new XxxException()`） | 异常**类型**（可多个，逗号分隔） |
| 效果 | **结束当前方法**，下面的代码不执行 | 不结束方法，只做声明；运行时异常一般可省略 |

### 自定义异常
- 做法：建类 → 继承某个异常 → 提供**空参 + 带参构造**（带参里 `super(message)`）
- 多数继承 **`RuntimeException`**：继承 `Exception` 会让它变成受检异常，每个调用处都被迫 `try-catch` 或 `throws`，方法签名被污染
- **必须继承 `Exception` 的场景**：业务上要求调用方**必须显式处理**的（支付失败、库存不足等），不处理就是错

## 补充：finally（课程未讲，10 分钟级）

1. **`finally` 一定执行**，即使 try 里 `return`——先算好返回值暂存，执行完 finally 再返回
2. **`finally` 里写 `return` 会覆盖** try 的 return（事故级写法，别用）
3. **唯一不执行的情况**：`System.exit()` 结束 JVM，或 JVM 崩溃 / 断电

```java
// 例：try 里 a=20 后 return，finally 把 a 改成 30 并打印
// 输出：finally: 30  →  20
// 返回的是已暂存的 20，finally 里改 a 不影响返回值
```

## LeetCode 387 字符串中的第一个唯一字符 ✅（week07 配额 3/5）

**方案：`int[26]` 数组计数**（先问过「用 Map 合适吗」，结论：数组更优）
```java
int[] cnt = new int[26];
for (int i = 0; i < s.length(); i++) cnt[s.charAt(i) - 'a']++;   // ① 数次数
for (int i = 0; i < s.length(); i++)                             // ② 按原顺序找 1
    if (cnt[s.charAt(i) - 'a'] == 1) return i;
return -1;
```
- **通过 107/107，6ms（击败 78.78%），内存 46.35MB**
- 核心认知：**字符 - 'a'** 把 `a~z` 映射到下标 `0~25`；等价于用下标当键的 Map
- **数组 vs Map**：键的取值范围小且连续（26 字母 / 128 ASCII）→ 数组；范围大或未知 → Map。本题用 Map 也能过，但每个 `char` 要装箱成 `Character`，慢 5–10 倍
- 第二趟必须**遍历原字符串**而不是数组，因为数组下标是字母序，丢了出现顺序
